# Present decisions through evidence

Based on Kole Jain’s UX/UI tutorials. These are unofficial, AI-assisted study notes and adapted skills; they were not written, approved or endorsed by Kole Jain. Permission has not been obtained from him.

[Source credit and reuse limits](../../SOURCE-MATERIAL.md)

## Mental model

A strong presentation connects a design to the problem it addresses. Before/after comparisons, user context, and the reason for a choice are more informative than a gallery of finished screens.

## When this skill applies

Use for design reviews, case studies, agent handoffs, and portfolio explanations.

## Reasoning

Start with the observable problem and the intended outcome. Select evidence that shows the mechanism changed. Keep before and after comparisons fair: the same task and comparable content should be visible.

Explain a few consequential decisions with their tradeoffs. Distinguish measured results, observed behavior, assumptions, and proposed work. State limitations so a reviewer can judge the actual evidence.

## Worked example — original implementation adaptation

An agent’s redesign handoff

Before: “Improved UX and made it modern” accompanies a polished final screenshot.

After: the handoff shows the original ambiguity, the new action hierarchy, a completed task and its failure recovery. It names tests run and any platform or user validation still missing.

## Failure modes

- Invented user research or conversion improvements.

- Comparisons that change both content and design without explaining it.

- A long process story that hides the final decision and evidence.

## Evidence that would support the decision

A reviewer should be able to identify what changed, why it helps the task, what was observed, and what remains uncertain.
